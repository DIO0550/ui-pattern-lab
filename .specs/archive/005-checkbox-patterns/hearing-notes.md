# Hearing Notes: Checkbox Design Patterns

## 目的

`ui-pattern-lab` にチェックボックスのデザインパターンを追加し、単なる見た目のバリエーション紹介ではなく、どのような場面でチェックボックスを選ぶべきか、他のコントロールを選ぶべき場面はどこかまで説明できる解説コンテンツを作る。

## スコープ

- **種別**: 新規機能
- **影響範囲**: 新規コンテンツ追加を中心に、既存ナビゲーションやカテゴリ一覧の更新を伴う可能性あり
- **優先度**: 高

## 技術的詳細

- **技術スタック**: TypeScript / React / MDX
- **フレームワーク**: Docusaurus 3.x
- **依存関係**: 既存の Docusaurus / React 構成を前提とし、新規ライブラリ追加は原則避ける
- **データ構造**: 既存の pattern entries と同様に、各チェックボックスパターンへ用途、適した場面、避けるべき場面、他コントロールとの比較観点を持たせる構成を優先する

## 品質要件

- **エッジケース**: 単独選択と複数選択、indeterminate state、disabled/error state、長いラベル、モバイルでのタップ領域、アクセシビリティ表現
- **エラーハンドリング**: コンテンツ欠落や entry ID の不整合は既存パターンに合わせてビルドや表示で明示的に検知できる構成を優先する
- **テスト要件**: `pnpm typecheck` と `pnpm build` を必須とし、必要なら関連ページの手動確認を行う
- **パフォーマンス**: 静的コンテンツ中心のため特別なパフォーマンス要件はない

## 追加コンテキスト

- ユーザーがその場で回答できないため、要件は既知情報から補完している
- 比較対象として少なくとも checkbox / radio button / switch(toggle) / select を扱えるようにしたい
- コンテンツでは「選択モデル」「ユーザーの期待」「即時反映かどうか」「複数選択の可否」などの判断軸を明示したい
- exploration で、checkbox を独立カテゴリとして追加するか、既存カテゴリの一部として追加するかを確認する
